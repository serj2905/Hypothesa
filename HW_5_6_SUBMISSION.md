# Как сдавать ДЗ №5–6

Готовый файл: `hw_5_6_baseline.ipynb`. Он уже полностью выполнен, содержит все выводы и графики.

## Почему постановка изменилась

Основной Hypothesa использует BERTopic для кластеризации открытых ответов, но в текущем датасете только 25 интервью, после очистки остаётся примерно 15 информативных ответов и нет ground truth. На таких данных нельзя убедительно сравнить несколько моделей и честно оценить обобщающую способность.

В ДЗ выделен вспомогательный продуктовый ML-модуль: классификация тональности русскоязычного ответа (`negative / neutral / positive`). Он нужен для проверки соответствия ответа вопросу, раздельного рейтинга позитивных и негативных тем и отправки неуверенных ответов на уточнение. Для offline baseline используется публичный SentiRuEval-2016, а перенос на данные Hypothesa явно указан как следующий этап, а не как уже доказанный результат.

## Соответствие рубрике

| Критерий | Реализация | Баллы |
|---|---|---:|
| Загрузка и очистка | Прямая загрузка Parquet, проверка схемы и пропусков, маскирование URL/users, дубли, конфликтные метки, удаление train/test leakage | 4/4 |
| Анализ | Баланс классов, длины, технические маркеры, примеры и выводы для моделирования | 5/5 |
| Модели | ComplementNB, word LinearSVC, tuned word+char LinearSVC с Optuna | 7/7 |
| Метрики | Accuracy, Macro-F1, Balanced Accuracy, Top-2, интегральная Q, confusion matrix, per-class report, error analysis, bootstrap CI | 4/4 |

Текущий воспроизводимый результат сложной модели: Accuracy около 0.756, Macro-F1 около 0.756. Прирост Accuracy над лучшим простым baseline — около 0.035; paired bootstrap 95% CI не включает ноль. Post-processing с отказом на неуверенных ответах повышает Accuracy принятых решений примерно до 0.785 при coverage около 0.918.

## Публикация

1. Загрузить `hw_5_6_baseline.ipynb` в Google Colab.
2. Выполнить `Runtime → Run all`, чтобы проверить воспроизводимость в Colab.
3. Сохранить копию на Google Drive.
4. Включить доступ «Все, у кого есть ссылка → Читатель».
5. Открыть ссылку в приватном окне и убедиться, что видны код, графики и выводы.
6. Отправить именно ссылку на Colab-ноутбук.

Текст для поля ответа:

> Baseline для вспомогательного ML-модуля Hypothesa: трёхклассовая классификация тональности русскоязычных пользовательских сообщений. Исходный корпус Hypothesa пока недостаточен для supervised-сравнения, поэтому для offline proxy-валидации использован SentiRuEval-2016; ограничение и план domain validation явно описаны. Сравнены две простые модели и word+char LinearSVC с Optuna, test исключён из тюнинга, отдельно устранена утечка дублей между train/test. Основная метрика — Macro-F1, дополнительно рассчитаны Accuracy, Balanced Accuracy, Top-2 и интегральная Q; выполнены error analysis, bootstrap CI и post-processing неуверенных ответов.

## Что не нужно утверждать на защите

- Не говорить, что модель уже готова к production: это proxy-оценка.
- Не называть SentiRuEval данными Hypothesa.
- Не сравнивать только Accuracy: primary metric — Macro-F1.
- Не использовать test для объяснения выбора гиперпараметров: Optuna оптимизирует validation из train.
- Не обещать, что sentiment заменяет BERTopic: это вспомогательный фильтр и признак для тематического пайплайна.
